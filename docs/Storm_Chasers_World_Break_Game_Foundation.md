# Storm Chasers: World Break — Complete Foundation

## SECTION 1: GAME VISION
**Polished pitch:** *Storm Chasers: World Break* is a cinematic, social weather-survival adventure where players roam a living open world shaped in real time by storms that flood valleys, electrify forests, unveil hidden ruins, and summon rare storm creatures; players track weather fronts, build stormproof shelters, investigate anomalies, and rally servers to witness unforgettable world events like the iconic Lightning Serpent descending through thunderclouds.

**Genre blend:** Survival adventure + creature discovery/capture + cooperative world events + light base building + atmospheric exploration.

**Target audience:** Ages 10–24 Roblox players who like social co-op experiences, creature collecting, exploration, visual spectacle, and short-session excitement with long-term mastery.

**Emotional pillars:**
1. Awe (cinematic storms)
2. Tension (risk during severe weather)
3. Discovery (rare creatures/hidden zones)
4. Belonging (server-wide moments)
5. Mastery (forecasting, gear, resilient base design)

**Differentiation from common Roblox games:**
- Weather is the core system, not a random visual modifier.
- Exploration and observation outperform raw stat grinding.
- Social spectacle purchases benefit entire servers.
- Creature encounters are tied to environmental conditions and timing.
- Strong “watchability loop” for clips/thumbnails.

**Why highly shareable:** Each session naturally produces clip-worthy events (storm walls, lightning creature spawns, meteor nights, eclipses, auroras) that are unpredictable but readable enough for viewers to instantly understand.

## SECTION 2: CORE GAMEPLAY LOOP
**First-session loop (0–30 min):**
1. Spawn in safe hub with tutorial forecast board.
2. Follow first storm beacon to gather basic materials.
3. Encounter first mild weather hazard + shelter need.
4. Spot first uncommon creature tied to weather.
5. Build a tiny storm-safe outpost module.
6. Join a server alert for mini event (e.g., ion rain).
7. Return to hub to unlock first scanner upgrade.

**Mid-game loop (days 2–10):**
- Track biome-specific weather windows.
- Craft better traversal + resistance tools.
- Build specialized shelter modules (grounding rods, flood gates).
- Study/capture rare creatures for research perks.
- Join timed server events for legendary materials.

**Long-term retention loop (weeks+):**
- Master forecast tech trees and biome mastery.
- Complete creature journal and anomaly archives.
- Build signature showpiece bases in high-risk zones.
- Host or trigger social celestial spectacles.
- Chase seasonal legendary hybrid storms.

**Co-op/social loop:**
- Squad roles: Forecaster, Builder, Tracker, Rescuer.
- Shared “Storm Alert” calls pull the whole server to hotspots.
- Group objectives scale rewards by participation quality, not combat DPS.

**Risk/reward structure:**
- The rarer the storm, the higher the hazard and drop quality.
- Evacuation decisions matter: overstay yields rare finds but risks gear durability/resource loss.
- Smart preparation (forecasting + base design) increases survival and yield.

## SECTION 6: BUILDING / BASE SYSTEM
**Philosophy:** “Build for weather stories, not static housing.” Bases are modular storm labs/shelters that visibly react to environmental stress.

**How weather threatens weak builds:**
- Wind applies structural load to exposed walls.
- Floodwater damages low-elevation electronics.
- Lightning fries ungrounded modules.
- Ash clogs turbines unless filtered.

**Defenses and systems:**
- Grounding Rod Network
- Flood Gate + Raised Foundation
- Reinforced Anchor Beams
- Storm Shutters (auto-close)
- Air Filter Stack (ash/sand)
- Thermal Buffer Panels

**Storm-resistant materials/modules:**
- Conductive Copper Lattice (redirect lightning)
- Sealed Composite Plating (hail/sand)
- Flexwood Frame (wind resilience)
- Hydrophobic Glass (visibility during rain)
- Shock Foam Insulation (impact mitigation)

**Keeping it fun:**
- Snap-based modular construction.
- No full base wipe; damage is repairable and readable.
- “Build Blueprints” shareable socially.
- Event modules create visual flair (light towers, aurora projectors).

- Data services

**StarterPlayer:**
- Client controllers (UI, weather visuals, alerts, input)

**StarterGui:**
- HUD root, storm tracker panel, event banner, creature journal

**Script type guidance:**
- **ModuleScripts:** reusable domain logic.
- **Scripts (server):** orchestration and authority.
- **LocalScripts:** rendering, camera, UI, local prediction only.

**Remote events/functions needed:**
- `WeatherStateChanged` (server→clients)
- `StormEventBroadcast` (server→clients)
- `CreatureEncounterEvent` (both directions with validation)
- `StormSeedPurchaseRequest` (client→server)
- `JournalSyncRequest` (client↔server function)

**Naming conventions:**
- PascalCase for modules/classes.
- camelCase for locals/functions.
- `*_CONFIG` constants for static config tables.

**Data persistence:**
- Profile-based DataStore wrapper with session lock.
- Save: journal discoveries, tech unlocks, base blueprints, cosmetics.
- Use ordered backup snapshots for recovery.

**Performance + replication:**
- Server computes authoritative weather state every tick window (e.g., 1 sec).
- Clients render heavy VFX locally based on compact replicated state.
- Creature AI runs server-side; client gets animation hints.
- Spatial partition checks for storm effects.

**Anti-exploit:**
- Never trust client purchase/event triggers.
- Validate proximity, cooldowns, entitlement.
- Clamp remote frequencies.
- Server-side reward calculation and encounter resolution.

**Server-authoritative weather:**
- A single WeatherManager controls active events.
- Deterministic scheduler + seeded RNG.
- Clients only receive state packets and visual directives.

### 1) WeatherManager module
**Place in:** `ServerScriptService/Systems/Weather/WeatherManager.lua`
```lua
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Remotes = ReplicatedStorage:WaitForChild("Remotes")

local WeatherStateChanged = Remotes:WaitForChild("WeatherStateChanged")

local WeatherManager = {}
WeatherManager.__index = WeatherManager

function WeatherManager.new(config)
    local self = setmetatable({}, WeatherManager)
    self.config = config
    self.currentWeather = nil
    self.weatherStartedAt = 0
    self.weatherDuration = 0
    return self
end

function WeatherManager:SetWeather(weatherId, duration)
    self.currentWeather = weatherId
    self.weatherStartedAt = os.clock()
    self.weatherDuration = duration

    WeatherStateChanged:FireAllClients({
        weatherId = weatherId,
        startedAt = self.weatherStartedAt,
        duration = duration,
    })
end

function WeatherManager:GetCurrentWeather()
    return self.currentWeather
end

function WeatherManager:IsWeatherExpired()
    if not self.currentWeather then
        return true
    end
    return (os.clock() - self.weatherStartedAt) >= self.weatherDuration
end

return WeatherManager
```

### 2) Storm event scheduler
**Place in:** `ServerScriptService/Systems/Weather/StormScheduler.lua`
```lua
local StormScheduler = {}
StormScheduler.__index = StormScheduler

function StormScheduler.new(weatherManager, weatherPool)
    local self = setmetatable({}, StormScheduler)
    self.weatherManager = weatherManager
    self.weatherPool = weatherPool
    self.rng = Random.new()
    return self
end

local function weightedPick(rng, entries)
    local total = 0
    for _, item in ipairs(entries) do
        total += item.weight
    end

    local roll = rng:NextNumber(0, total)
    local cursor = 0
    for _, item in ipairs(entries) do
        cursor += item.weight
        if roll <= cursor then
            return item
        end
    end
    return entries[#entries]
end

function StormScheduler:Step()
    if not self.weatherManager:IsWeatherExpired() then
        return
    end

    local nextWeather = weightedPick(self.rng, self.weatherPool)
    self.weatherManager:SetWeather(nextWeather.id, nextWeather.duration)
end

return StormScheduler
```

### 3) Lightning storm system
**Place in:** `ServerScriptService/Systems/Weather/LightningStormSystem.lua`
```lua
local Players = game:GetService("Players")

local LightningStormSystem = {}
LightningStormSystem.__index = LightningStormSystem

function LightningStormSystem.new(weatherManager)
    local self = setmetatable({}, LightningStormSystem)
    self.weatherManager = weatherManager
    self.tickAccumulator = 0
    return self
end

function LightningStormSystem:Update(deltaTime)
    self.tickAccumulator += deltaTime
    if self.tickAccumulator < 1 then
        return
    end
    self.tickAccumulator = 0

    if self.weatherManager:GetCurrentWeather() ~= "Thunderstorm" then
        return
    end

    for _, player in ipairs(Players:GetPlayers()) do
        local character = player.Character
        local hrp = character and character:FindFirstChild("HumanoidRootPart")
        local humanoid = character and character:FindFirstChildOfClass("Humanoid")

        if hrp and humanoid and math.random() < 0.05 then
            -- Server-authoritative lightning damage tick.
            humanoid:TakeDamage(8)
        end
    end
end

return LightningStormSystem
```

function WetSurfaceService:Apply()
    local weather = self.weatherManager:GetCurrentWeather()
    local isWet = weather == "Drizzle" or weather == "Thunderstorm" or weather == "Monsoon"

    for _, part in ipairs(CollectionService:GetTagged("WeatherReactive")) do
        if part:IsA("BasePart") then
            part.Material = isWet and Enum.Material.SmoothPlastic or Enum.Material.Grass
            part.Reflectance = isWet and 0.12 or 0
        end
    end
end

return WetSurfaceService

### 5) Lightning Serpent spawn controller
**Place in:** `ServerScriptService/Systems/Creatures/LightningSerpentController.lua`

local ReplicatedStorage = game:GetService("ReplicatedStorage")

function LightningSerpentController.new(weatherManager, serpentTemplate)

    self.weatherManager = weatherManager
    self.serpentTemplate = serpentTemplate
    self.activeSerpent = nil
    self.cooldownUntil = 0

end

function LightningSerpentController:TrySpawn()
    if os.clock() < self.cooldownUntil then
        return
    end

    if self.weatherManager:GetCurrentWeather() ~= "WorldbreakerSupercell" then
        return
    end

    if self.activeSerpent then
        return
    end

    self.activeSerpent = self.serpentTemplate:Clone()
    self.activeSerpent.Parent = Workspace:WaitForChild("StormRuntime")
    self.activeSerpent:PivotTo(CFrame.new(0, 220, 0))

    self.cooldownUntil = os.clock() + 600
    StormEventBroadcast:FireAllClients({
        eventId = "LightningSerpentAppears",
        message = "⚡ The Lightning Serpent descends from the storm!",
    })
end

return LightningSerpentController

### 6) Lightning Serpent simple AI behavior
**Place in:** `ServerScriptService/Systems/Creatures/LightningSerpentAI.lua`
```lua
local Players = game:GetService("Players")

local LightningSerpentAI = {}
LightningSerpentAI.__index = LightningSerpentAI

function LightningSerpentAI.new(serpentModel)
    local self = setmetatable({}, LightningSerpentAI)
    self.model = serpentModel
    self.time = 0
    self.targetPlayer = nil
    return self
end

function LightningSerpentAI:PickTarget()
    local list = Players:GetPlayers()
    if #list == 0 then
        self.targetPlayer = nil
        return
    end
    self.targetPlayer = list[math.random(1, #list)]
end

function LightningSerpentAI:Update(deltaTime)
    if not self.model or not self.model.Parent then
        return
    end

    self.time += deltaTime
    if self.time % 8 < deltaTime then
        self:PickTarget()
    end

    local root = self.model.PrimaryPart
    if not root then
        return
    end

    local basePos = root.Position
    local arcOffset = Vector3.new(math.sin(self.time * 1.2) * 25, math.cos(self.time) * 8, math.cos(self.time * 0.8) * 25)

    if self.targetPlayer and self.targetPlayer.Character and self.targetPlayer.Character:FindFirstChild("HumanoidRootPart") then
        local targetPos = self.targetPlayer.Character.HumanoidRootPart.Position + Vector3.new(0, 35, 0)
        local desired = targetPos + arcOffset
        self.model:PivotTo(CFrame.lookAt(desired, targetPos))
    else
        self.model:PivotTo(CFrame.new(basePos + arcOffset))
    end
end

return LightningSerpentAI
```

### 7) Example creature encounter loop
**Place in:** `ServerScriptService/Systems/Creatures/CreatureService.lua`
```lua
local CreatureService = {}
CreatureService.__index = CreatureService

function CreatureService.new(lightningSerpentController)
    local self = setmetatable({}, CreatureService)
    self.lightningSerpentController = lightningSerpentController
    self.activeEncounters = {}
    return self
end

function CreatureService:BeginEncounter(player, creatureId)
    local encounterId = string.format("%d_%s_%d", player.UserId, creatureId, os.time())
    self.activeEncounters[encounterId] = {
        playerUserId = player.UserId,
        creatureId = creatureId,
        startedAt = os.clock(),
        stage = "Track",
    }
    return encounterId
end

function CreatureService:AdvanceEncounter(encounterId)
    local encounter = self.activeEncounters[encounterId]
    if not encounter then
        return nil
    end

    if encounter.stage == "Track" then
        encounter.stage = "Calm"
    elseif encounter.stage == "Calm" then
        encounter.stage = "Capture"
    else
        encounter.stage = "Complete"
    end

    return encounter.stage
end

return CreatureService
```

    StormSeedPurchaseRequest.OnServerEvent:Connect(function(player, stormId)
        self.pendingPurchases[player.UserId] = stormId
        MarketplaceService:PromptProductPurchase(player, STORM_SEED_PRODUCT_ID)
    end)

    MarketplaceService.ProcessReceipt = function(receiptInfo)
        local stormId = self.pendingPurchases[receiptInfo.PlayerId]
        if stormId then
            self.weatherManager:SetWeather(stormId, 180)
            self.pendingPurchases[receiptInfo.PlayerId] = nil
        end
        return Enum.ProductPurchaseDecision.PurchaseGranted
    end
end

return StormSeedService

## SECTION 14: UI / UX PLAN
**HUD:** minimal bars (health/stamina/exposure), compass, current weather state badge.

**Storm tracker:** radar-like panel showing active fronts, severity color, ETA.

**Creature alerts:** non-intrusive directional pulse + icon + soft audio cue.

**Inventory/journal:** split tabs (Materials, Tools, Creatures, Weather Archive); instant visual stamps for new discoveries.

**Monetization surfaces:**
- Event kiosk in hub (spectacle-first framing)
- Optional quick-buy in event panel
- Clear “server benefits” explanation before purchase

**Event notifications:** top-center cinematic banners with iconography and short verbs (“Seek Shelter”, “Serpent Descending”).

**Beauty + clarity principles:**
- Max 3 persistent UI anchors.
- Contextual cards fade in/out near relevant events.
- Use weather-color language: cyan(normal), amber(rare), magenta(legendary).

## SECTION 15: ART DIRECTION GUIDE
**Color palettes:**
- Base world: natural greens/earth tones.
- Storm states: cobalt, violet, silver-white highlights.
- Legendary events: high-contrast magenta/cyan accents.

**Lighting mood:**
- Wide dynamic range, darker storm mids, strong lightning key flashes.
- Golden calm periods to heighten storm contrast.

**Materials:**
- Wetness readable via reflectance and roughness shifts.
- Biome-specific micro detail (ash dust, marsh sheen, crystal sand sparkle).

**Particle style:**
- Layered and directional (foreground droplets + distant sheets).
- Avoid noisy spam; prioritize silhouette and readability.

**Creature silhouettes:**
- Distinct from terrain shape language.
- Exaggerated profile readable from distance (especially Serpent).

**Environment storytelling:**
- Ruined weather stations, torn warning banners, grounded lightning towers.
- Visual clues that teach survival systems without text.

**Thumbnail/key art ideas:**
1. Lightning Serpent spiraling above players on a glowing ridge.
2. Team repairing base while meteor shower reflects in marsh.
3. Aurora over floating sky deck with crowd silhouettes.

## SECTION 16: RISKS AND SOLUTIONS
**Design risks:**
- Overcomplex systems early → *solution:* MVP with 1 biome + 3 weather types.
- Player confusion → *solution:* forecast board + event callouts + role hints.

**Technical risks:**
- Weather VFX performance drops → *solution:* client LOD and state-driven FX presets.
- Server load from AI/weather checks → *solution:* 1-second authority ticks + spatial partition.

**Monetization risks:**
- Perceived pay-to-win from event triggers → *solution:* equalized loot/caps and transparent rules.
- Too many purchase prompts → *solution:* hub-centric optional kiosk + low-frequency prompts.

**Scope reduction strategy:**
- Protect core pillars: cinematic weather, social events, creature moments.
- Defer advanced biome count, cosmetic volume, and deep building complexity.
